cpp-data-structures

C++20header-onlyASan · UBSan · TSan

A header-only C++20 library of data structures in namespace dsl: a dynamic array, singly and doubly linked lists, a ring buffer, stack and queue adapters, an unbalanced binary search tree, an AVL tree, a Robin Hood open-addressing hash map, and a binary heap. Memory is managed by hand with RAII, the rule of five and allocator support. Every container is tested against its std:: counterpart and benchmarked against it. This is a 2026 rebuild of a 2023 project whose code was not kept.

Source: github.com/darshpandya02/cpp-data-structures (the README has the full benchmark table for n = 1k to 1M)

What the recording shows

  • A fresh clone and a build of the tests, the demo program and the benchmark.
  • The unit tests: 64 doctest cases with 978,254 assertions, all passing. They include randomized runs that apply thousands of operations to each container and to its std:: counterpart and compare the two after every operation.
  • The same tests built with -fsanitize=address,undefined and then with -fsanitize=thread. Both pass with no sanitizer reports.
  • A leak check with macOS leaks: 0 leaks. LeakSanitizer does not run on Apple silicon. On Linux, CI runs ASan with leak detection, using g++ and clang++.
  • dsl-demo avl inserts 10, 20, 30, 40, 50, 25 and draws the tree after each insert. 30 and 50 each trigger a single rotation, and 25 needs a double rotation. The tree's own validate() check passes after every step.
  • Inserting 1 to 10,000 in sorted order: the plain BST reaches height 10,000 (a linked list), while the AVL tree stays at height 14.
  • The hash map growing from 0 to 2,048 buckets as 1,000 keys go in, with the load factor and the longest probe at each rehash. Then half the keys are erased by backward shift, with no tombstones.
  • A short benchmark (n = 1k and 100k) against std::vector, std::list, std::map, std::unordered_map, std::priority_queue and std::queue. The std containers win some rows. std::queue is faster at push+pop, for example, and the hash map is faster at erase and iteration.

Other heavy jobs were running on the laptop during this recording (load average around 12), so the short benchmark's numbers are noisier than the README's table, which was measured on a quieter machine at n = 1k to 1M. The benchmark alternates dsl and std runs and reports medians, so the ratios are more stable than the absolute times. Build steps are also slow under that load, and pauses longer than 2 s are shortened on playback.
