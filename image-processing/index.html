image-processing-application

JavaMVCSwing

An image editor in plain Java, with no libraries beyond the JDK. It follows a model-view-controller design. Images are loaded into a model under a name, operations create new named images, and save writes PNG, JPG or plain-text PPM. There are three front ends: a Swing GUI (no arguments), a text mode (-text) that reads commands from standard input, and a script mode. Script mode is the run FILE command, or -file FILE, which opens the GUI.

The operations are the red, green, blue, value, luma and intensity components, horizontal and vertical flips, brighten or darken, RGB split and combine, blur, sharpen, sepia, histogram, color correction, levels adjustment and Haar-wavelet compression. Most filters also take split P, which applies the filter to only the left P percent of the image for a side-by-side preview.

What the recording shows

  • A fresh clone compiled with javac, giving 13 classes.
  • The start of the help text, printed by the text controller.
  • A 25-line script that loads the sample image from res/, applies 12 operations (including a split-view sepia), and saves the results as PNG, JPG and PPM. It runs through run in text mode, so no window opens. The outputs are then listed, and file confirms their formats and sizes (the histogram is 256×256).
  • The repository's own res/commands.txt (155 lines, 80 saves). It covers every operation on the PNG, JPG and PPM copies of the sample and takes about 23 s.
  • Error handling: a missing file and an unknown image name each print an error, and the session carries on.

Before this recording, res/commands.txt used an image called input without loading it first, so the script stopped at the first compress. It now loads res/input.jpg as input, the same way res/jarCommand.txt does (commit 290b788).
